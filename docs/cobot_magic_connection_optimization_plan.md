# COBOT MAGIC 上位机自动化连接与新机一键部署优化方案

> 适用仓库：`EDDY-YANG/cobot-magic-workbench`（覆盖 `server/`、`lab_stack/agilex_control/`、`client/`、`tools/` 及 `web/`）

## 1. 背景与优化目标

当前 4090 中央主机与 AgileX 机械臂主机通过网线直连协作，但实际使用中存在“旧链路容易因重启/拔插/隧道脱节卡死”**以及**“换一台新电脑直连机械臂必须手动改网口 IP 和配 SSH 公钥”两大痛点。本方案旨在不破坏现有安全守卫的前提下，达成以下目标：

1. **上位机网页一键打通链路**：网线直连 4090 与机械臂后，在前端「系统总览」或「任务起始页」点击一次「一键连接机械臂」，后端按固定状态机自动完成 SSH 探测、USB 核验、会话绑定刷新以及设备代理 / 采集 Hub / 反向隧道拉起，并实时反馈进度与具体卡点。

2. **新主机开箱即连（预设初始化程序）**：在任意新电脑上安装上位机时，通过机械臂端免改 IP 机制（轻量 DHCP）+ 本地一键初始化向导，自动完成网口连通、SSH 密钥生成、公钥授权写入与配置文件生成。

3. **严守真机安全底线**：自动化连接仅打通通信与观测采集，绝不自动加载模型、不自动解除 `STOP` 锁存、不重放运动指令、不静默覆盖代码版本。

## 2. 现有连接链路 7 大核心问题盘点

结合仓库现有实现（`docs/architecture.zh-CN.md`、`docs/recovery.md`、`lab_stack/agilex_control/web_backend.py`、`lab_stack/agilex_control/pc.py`、`server/reconcile.py`）与日常硬件接入痛点，整理如下：

| 编号 | 问题类别 | 具体表现与触发场景 | 代码根因 / 原理定位 | 
| ----- | ----- | ----- | ----- | 
| **P1** | **重启后 Boot ID 绑定失效** | 4090 或机械臂正常重启后，直接报 `BOOT_SESSION_CHANGED` 或 `Acceptance is stale`，无法直接恢复连接 | 旧版 profile 将软件代码 SHA、USB 设备号与主机 `Boot ID` 耦合在一起，重启导致整条元数据链失效（见 `docs/architecture.zh-CN.md`） | 
| **P2** | **USB 拔插与未选盘拦截** | U 盘重新插拔后设备号变化，或未先扫描选盘时点击连接，直接卡在 `USB_IDENTITY_UNCONFIRMED` | `pc.py` 与 `web_backend.py` 强制校验 `os.path.ismount` 与 `findmnt UUID`，绝不降级写本地盘；连接前必须完成显式扫描与选盘 | 
| **P3** | **源码指纹不一致与同步死锁** | 修改代码后直接连接报 `SOURCE_IDENTITY_MISMATCH`；点同步又提示“请先断开页面通道” | `connect` 阶段执行 `pc.check_sources` 逐文件核对 4090 与设备端 U 盘哈希；旧版双向同步还存在将未提交代码带入生产的风险 | 
| **P4** | **反向隧道脱节（“假在线”）** | 主 SSH 连通、网页显示在线，但切换 V2 或模型路线时报错 `TIMEQP_UNAVAILABLE` | 主 SSH、`TimeQP`（18970 反向隧道）与模型推理反向隧道原先各自独立恢复，缺少统一的链路就绪判定（见 `docs/recovery.md`） | 
| **P5** | **旧 Hub 进程残留与控制权锁死** | 上次异常断开后共享采集 `Hub` 仍存活占端口，或超时盲目重试导致 Owner 状态不明 | `Hub` 生命周期独立于单次网页 CLI 任务（`web_backend.py`），异常中断后若缺少统一探测与幂等复用，易与既有任务和 `STOP` 冲突 | 
| **P6** | **主机多网口静态 IP 绑定与换口失联** | 换插电脑的另一个网口即连不上；换一台新主机直连机械臂必须先手动修改网口静态 IP，且易误配网关导致 Wi-Fi 断网 | IP 绑定在单个物理网卡（而非整台电脑），直连无路由器时默认无法自动获取同网段 IP | 
| **P7** | **新主机 SSH 公钥缺失导致连接被拒** | 新电脑直接运行上位机连机械臂时直接失败，无引导提示 | `pc.py` 为实现自动化强制使用 `BatchMode=yes` 与 `StrictHostKeyChecking=yes`，未预先写入机械臂 `~/.ssh/authorized_keys` 时会直接拒绝连接 | 

## 3. 总体优化架构设计

将整个连接体系拆分为**底层免配网络**、**新机初始化向导**、**后端一键编排接口**与**前端分步反馈**四个解耦层：

### 模块 A：网络层“免改 IP”改造（解决 P6）

1. **机械臂端开启轻量级 DHCP 服务（推荐主力方案）**

   * 在机械臂主机（固定不变的一端）的直连有线网口上固定静态 IP（例如 `192.168.10.2/24`）。

   * 在该网口上部署轻量级 `dnsmasq` DHCP 服务，自动为插上网线的对端主机分配同网段地址（如 `192.168.10.10 ~ 192.168.10.50`）。

   * **关键防坑配置**：在 `dnsmasq` 中**显式置空默认网关与 DNS 下发**（`dhcp-option=3` 与 `dhcp-option=6` 为空），确保对端 4090 或新笔记本插上网线直连机械臂时，**Wi-Fi 或另一根外网网线照常上网，绝不抢占默认路由**。

   * **收益**：任意新电脑保持系统默认的“自动获取 IP”，**随便插哪个网口都能在 2 秒内自动连通 `192.168.10.2`**，彻底消除换口失联和手动改 IP 的麻烦。

2. **辅以 mDNS 域名广播（零配置兜底）**

   * 机械臂启用 Ubuntu 自带的 `avahi-daemon`，广播固定局域网主机名（如 `agilex-robot.local`），方便排错时免记 IP。

3. **物理标识规范（面向固定 4090 主机）**

   * 若实验室暂不在机械臂端开 DHCP，则在固定 4090 主机的直连网口贴物理标签固定插口，并由模块 B 的脚本自动识别活跃载波网口。

### 模块 B：新电脑预设初始化程序（解决 P6、P7）

在仓库 `tools/` 下新增跨平台初始化程序（如 `tools/setup_host_link.py`，并提供 Windows `.cmd` / Linux `.sh` 一键双击入口），新电脑安装上位机后仅需运行一次：

1. **自动探测直连网口与连通性**

   * 扫描本机有线网卡载波状态（Carrier Up），优先测试是否已通过机械臂 DHCP 自动连通 `192.168.10.2`。

   * 若未检测到 DHCP，则自动列出所有活跃有线网卡，用户选择插着网线的那张网卡后，脚本自动为其写入同网段静态 IP（不设默认网关，保护 Wi-Fi），并立即 `ping` 验证。

2. **自动生成本机专属 SSH 密钥对**

   * 检查 `~/.ssh/id_ed25519` 是否存在；若不存在，自动执行 `ssh-keygen -t ed25519 -N ""` 生成本机专属私钥（留在本地）与公钥（`.pub`）。

3. **双模式自动写入公钥（兼顾日常便捷与高安全）**

   * **模式 1（机械臂允许首次密码登录）**：脚本检测免密未通过时，引导用户输入**仅此一次**的机械臂登录密码，自动调用 `ssh-copy-id` 将公钥追加写入机械臂 `~/.ssh/authorized_keys`，并记录主机指纹（`known_hosts`）。

   * **模式 2（机械臂已关闭 `PasswordAuthentication` 高安全模式）**：脚本自动导出单行 `.pub` 公钥文件并提示“将此文件发给管理员或用 U 盘追加至机械臂白名单”，同时提供“重新检测免密连通”按钮。

4. **自动生成上位机配置文件**

   * 自动写入或更新 `~/.ssh/config` 中的固定别名块（如 `Host agilex-robot`，指向机械臂 IP、`BatchMode yes`、`StrictHostKeyChecking yes`、`ConnectTimeout 8`）。

   * 自动生成或校验 `server/installation.local.json` 中的主机身份与 `ssh_alias` 字段，避免手工改 JSON 出错。

5. **一键连通性验收**

   * 自动运行一次只读探针（验证 SSH 免密、机械臂 `hostname`、USB 盘可见性），全部绿灯后提示“初始化完成，可启动上位机”。

### 模块 C：后端“一键连接机械臂”统一编排接口（解决 P1–P5）

在 `server/main.py` 中新增受守卫的编排接口 `POST /platform/connect`（及配套的进度查询或流式状态字段），由 4090 后端按严格 4 阶段状态机串联既有能力，替代原来分散的手工排错：

| 阶段 | 执行动作 | 解决的历史问题 | 失败时的明确处理 | 
| ----- | ----- | ----- | ----- | 
| **Stage 1：网口与 SSH 探测** | 校验 `ssh_alias` 免密连通性与延迟，确认目标 `hostname` 匹配 | P6、P7 | 区分“网线未插/IP 不通”与“公钥未授权”，直接给出修复指引，不进入后续阶段 | 
| **Stage 2：USB 自动扫描与核验** | 调用 `web_backend.py` 的 `_scan_storage`（只读探针），核对 `findmnt UUID` 与挂载点 | P2 | 若仅发现 1 块已登记白名单 U 盘则自动选中并刷新设备号；若发现多块或新 U 盘，暂停并由前端弹窗请操作员显式确认 | 
| **Stage 3：会话绑定与源码核对** | 读取最新 `Boot ID`，若与上次不一致则调用 `reconcile.prepare_session` 刷新会话绑定；运行 `pc.check_sources` 校验代码指纹 | P1、P3 | 重启后自动重建会话绑定且**保留旧验收记录不改写为 PASS**；若源码哈希不一致则阻断并提示显式执行“同步代码”，绝不静默覆盖 | 
| **Stage 4：原子化拉起与隧道对齐** | 接通 `web_agent`；检测既有 `Hub` 是否健康（健康则幂等复用，异常残留则受控回收后再拉起）；同步拉起并校验 `TimeQP:18970` 反向隧道 | P4、P5 | 只有主链路、`web_agent`、`Hub` 与 `TimeQP` 全部通过健康检查才回报“链路就绪”；若某一项失败则精准标出受阻组件 | 

* **幂等与防重放机制**：沿用 `docs/recovery.md` 的持久化 `PENDING` 意图锁——若连接过程中发生超时或断网，不盲目并发重试；下次查询只观测实际状态，避免重复拉起僵尸进程或冲掉活动任务控制权（Owner）。

### 模块 D：前端引导交互对接

1. **入口布局**：在「系统总览与拓扑」面板右上角及「任务起始页」硬件状态条放置统一的 **「⚡ 一键连接机械臂」** 按钮（在线时转为「↻ 重新校验连接」）。

2. **4 阶段实时可视化反馈**：点击后展开 4 步状态条（网口与 SSH 探测 → USB 物理核验 → 会话与源码绑定 → 代理 / Hub / 隧道），每步独立显示耗时与通过/受阻原因。

3. **可操作排错引导**：若卡在 Stage 2（多盘/未插盘）直接在卡片内提供“重新扫描 / 选盘”；若卡在 Stage 3（源码不一致）提供“先断开并显式同步源码”快捷入口。

## 4. 必须严守的安全边界（红线清单）

在实现连接自动化与新机一键配置的过程中，以下 5 条安全边界**不得放松**：

1. **绝不自动加载模型**：连接打通后模型状态保持 `OFF`（未加载），需操作员进入操作台显式选择权重加载。

2. **绝不自动解除 `STOP` 锁存**：检测到 `STOP_LATCHED` 时只如实上报，必须由操作员确认物理环境安全后手动解除。

3. **绝不自动重放运动或录制指令**：网络超时或重连后仅恢复只读状态观测，严禁重发任何历史动作命令。

4. **绝不静默覆盖未核验源码**：源码指纹不匹配时阻断连接并要求显式同步，防止开发副本污染真机运行环境。

5. **绝不降级写入机械臂本地盘**：未核验合法 USB 物理身份前，保持录制与持久化操作受阻。

## 5. 分阶段实施路线与验收清单

| 阶段 | 改造范围 | 核心产出 | 验收方式 | 
| ----- | ----- | ----- | ----- | 
| **Phase 1：机械臂端免改 IP** | 机械臂主机系统网络配置 | 直连网口固定 IP + `dnsmasq`（无默认网关下发）+ `avahi` | 拿任意一台未改过 IP 的笔记本直插网线，2 秒内可 `ping` 通机械臂且 Wi-Fi 正常上网 | 
| **Phase 2：新机预设初始化向导** | 新增 `tools/setup_host_link.py` 及一键启动脚本 | 自动探测网口/配 IP、生成密钥、首次引导写公钥、生成 `~/.ssh/config` 与 `installation.local.json` | 在一台全新电脑上运行脚本，无需手工编辑配置文件即可通过 `ssh agilex-robot hostname` 免密测试 | 
| **Phase 3：后端一键连接接口** | `server/main.py`、`server/reconcile.py`、`lab_stack/agilex_control/web_backend.py` | `POST /platform/connect` 四阶段编排与 `PENDING` 锁、USB 自动刷新、Hub 幂等复用与 `TimeQP:18970` 联合检查 | 模拟机械臂重启、U 盘拔插、TimeQP 断开三种故障场景，单次调用接口可自动恢复就绪；运行 `python3 -B -m unittest discover -s tests -p "test_*.py" -v` 全绿 | 
| **Phase 4：前端对接与实机联调** | `web/` 及 `lab_stack/web/` | 对接 `POST /platform/connect` 与 4 阶段实时进度反馈 UI | 运行 `node --test tests/test_ui*.mjs` 通过；实机完成“拔网线 → 插网线 → 点一键连接 → 进入任务起始页”闭环验证 |
